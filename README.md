# HJEN Docs

A small, **static, zero-dependency** documentation site for the HJEN system — read and search all the docs in your browser. Because it's fully static, it can be **hosted for free** (HTTPS + global CDN) with no server and no database to run.

**Live:** https://itsdula.github.io/hjen-docs/ (published from this repo via GitHub Pages).

It documents the six repositories in `~/Dev/hjen` (what each does, how they depend on each other, the system architecture, a security review, and a beta-launch plan). It was generated by reading the repos; it changes **no** repo code and lives in its own folder alongside them.

## How it works

The docs are Markdown files in `docs/`. A tiny build step (`build.mjs`) bakes them into `public/docs.json`, and the browser app (`public/`) does all the listing, rendering, and search itself. So the deployable artifact is just the **`public/` folder** — plain static files.

```
hjen-docs/
  docs/            # the documentation, as Markdown (edit these to change content)
  build.mjs        # bakes docs/*.md → public/docs.json   (run before deploying)
  server.js        # optional local preview server (also runs the build)
  public/          # the static site you deploy: index.html, app.js, styles.css, docs.json
```

## Preview locally

Requires Node 18+ (nothing to install):

```bash
cd hjen-docs
node server.js          # builds docs.json, serves → http://localhost:4321
# PORT=8080 node server.js  to change the port
```

Or, since it's static, any static file server works after building once:

```bash
node build.mjs                 # writes public/docs.json
cd public && python3 -m http.server 4321
```

Use the search box (top-left) to search the full text of every page.

## Deploy it for free (easiest → still easy)

All three are free, give you HTTPS automatically, and need **no server, no database, no secrets**. The build command is always `node build.mjs` and the folder to publish is always `public`.

### Option 1 — Cloudflare Pages (recommended)
The simplest and most generous free tier. Two ways:

- **Drag-and-drop:** run `node build.mjs`, then at [Cloudflare Pages](https://pages.cloudflare.com) → "Upload assets" and drop the **`public/`** folder. Done — you get a `*.pages.dev` URL.
- **Connect a Git repo** (auto-deploys on every push): Framework preset **None**, Build command **`node build.mjs`**, Build output directory **`public`**.

### Option 2 — GitHub Pages (what this repo is set up for)
A workflow (`.github/workflows/deploy.yml`) is already included: on every push it runs `node build.mjs` and publishes `public/` to Pages. The site's asset paths are relative, so it works fine at the `/<repo>/` subpath, and a `public/.nojekyll` file is included. To go live:

```bash
cd hjen-docs
git init -b main
git add -A
git commit -m "HJEN system documentation site"
git remote add origin https://github.com/itsdula/hjen-docs.git
git push -u origin main
```

Then on GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**. The workflow runs and the site appears at **https://itsdula.github.io/hjen-docs/**. After that, every `git push` redeploys automatically.

### Option 3 — Netlify
Drag-and-drop the `public/` folder at [app.netlify.com/drop](https://app.netlify.com/drop), or connect the repo with build command **`node build.mjs`** and publish directory **`public`**.

## Updating the docs

Edit or add a Markdown file in `docs/` (named `NN-slug.md` — the two-digit prefix sets order and sidebar grouping), then:

- **Local:** just refresh (if using `node server.js`) — it rebuilds on start.
- **Deployed:** re-run `node build.mjs` and redeploy, or just `git push` if you connected a repo (Cloudflare/Netlify rebuild automatically).

Sidebar groups by the first prefix digit: `0x` Start here · `1x` The repositories · `2x` System & security · `3x` Beta launch · `4x` Reference.

## Cost

$0. Static hosting on any of the above stays within the free tier for documentation-sized traffic. The only thing that could ever cost money is adding a custom domain (the domain registration itself), which is optional.
